02 SELECT & FROM

Six rules for writing SQL

🔠 Case doesn't matter

select = SELECT. Write keywords in CAPITALS so they stand out.

➖ Commas between columns

SELECT name, city, -- ✗ extra FROM Students;

No comma after the last column.

⏹️ End with a semicolon

; marks where one statement ends. Good habit, required in some places.

💬 Comments

-- one line /* many lines */

SQL ignores them. Use them to explain your query.

🧱 Names with spaces

SELECT [Student Name]

Wrap unusual names in square brackets.

⭐ SELECT * : explore only

Fine to peek at a table. In reports, list the columns: faster, clearer, and safe if the table changes.

Bonus: SELECT 2 + 3 AS answer; works with no table. SQL is also a calculator.

03 Aliases & calculations

Three surprises when you calculate

➗ Whole ÷ whole = whole

SELECT 7 / 2; → 3 SELECT 7 / 2.0; → 3.5 SELECT 7 % 2; → 1 -- remainder

INT ÷ INT cuts off the decimals. Make one side a decimal to keep them.

🕳️ NULL swallows everything

'Mail: ' + NULL → NULL CONCAT('Mail: ', NULL) → 'Mail: ' 120 + NULL → NULL

Any math or + with NULL gives NULL. CONCAT treats NULL as empty text.

🏷️ Aliases have a lifetime

ORDER BY [Credits Left] ✓ WHERE [Credits Left] > 50 ✗ WHERE 144 - credits > 50 ✓

WHERE runs before SELECT, so it can't see the alias yet. More on this at the end.

05 ORDER BY

ORDER BY sorts the result

SELECT   name, cgpa
FROM     Students
ORDER BY cgpa DESC;
ASC small → big, A → Z, old → new. Default: you can leave it out.
DESC big → small, Z → A, new → old.
NULL counts as the smallest value: first in ASC, last in DESC.
⚠️ No ORDER BY = no guaranteed order. Never trust “it looked sorted”.

06 TOP & paging

OFFSET … FETCH: skip some rows, then take some

SELECT   name, cgpa
FROM     Students
ORDER BY cgpa DESC              -- required
OFFSET 3 ROWS                   -- skip 3
FETCH NEXT 3 ROWS ONLY;        -- take 3
📄 This is how websites show “page 2 of results”.
🧮 Page p with n per page: OFFSET (p−1)×n ROWS FETCH NEXT n ROWS ONLY
🔁 MySQL / PostgreSQL write it as LIMIT 3 OFFSET 3. Same idea, different dialect.

08 AND / OR / NOT

The trap: AND runs before OR

Goal: SWE or CSE students with a CGPA above 3.5.

✗ Without brackets: 6 rows

WHERE department = 'SWE' OR department = 'CSE' AND cgpa > 3.5

SQL reads it as SWE OR (CSE AND cgpa > 3.5), so every SWE student gets in, even low CGPAs.

RahimNusratNabil 3.10Riya NULLKarimSumaiya

✓ With brackets: 4 rows

WHERE (department = 'SWE' OR department = 'CSE') AND cgpa > 3.5

Brackets run first, then the CGPA rule applies to both departments.

Rahim 3.75Nusrat 3.90Karim 3.60Sumaiya 3.98
Order: ( ) → NOT → AND → OR. When you mix AND and OR, always use brackets.

IN: “is the value in this list?”

-- the long way
WHERE city = 'Dhaka' OR city = 'Chattogram'

-- the short way: same result
WHERE city IN ('Dhaka', 'Chattogram')
✓ 5 rows
Karim · DhakaTania · ChattogramFarhana · DhakaShafin · ChattogramRiya · Dhaka

12 NULL

NULL means “unknown”, not zero, not empty

0

A known number: Riya has 0 credits.

''

Known, but empty text: an email of zero characters.

NULL

We don't know: Riya's CGPA doesn't exist yet. Tania never gave an email.

✗ = NULL never works

SELECT name FROM Students WHERE email = NULL; → 0 rows

“Is unknown equal to unknown?” → unknown. Not TRUE, so no row passes.

✓ Use IS NULL / IS NOT NULL

WHERE email IS NULL; → Tania, Farhana, Arif WHERE email IS NOT NULL; → 9 rows

The only correct way to test for a missing value.

12 NULL

Three answers: TRUE, FALSE and UNKNOWN

TRUE

row is kept

FALSE

row is dropped

UNKNOWN

row is dropped too

WHERE cgpa < 3.5 → 6 rows WHERE cgpa >= 3.5 → 5 rows
6+5=11≠12Riya is in neither

“Is NULL < 3.5?” is UNKNOWN, and so is “NULL >= 3.5”. Rows with NULL silently vanish from both filters.

SELECT name,
  ISNULL(email, 'not given') AS email,
  COALESCE(cgpa, 0)          AS cgpa
FROM Students;
nameemailcgpa
Tanianot given3.20
Farhananot given3.45
Riyariya@lu.ac.bd0.00
ISNULL(x, y) if x is NULL, show y. SQL Server only.
COALESCE(a, b, c…) first non-NULL value. Standard SQL, works everywhere.

Putting it together

You write it in one order. SQL runs it in another.

SELECT name, cgpa AS gpa3
FROM Students1
WHERE city = 'Sylhet'2
ORDER BY gpa DESC;4
✓ Result · 5 rows
Sumaiya 3.98Nusrat 3.90Rahim 3.75Mim 3.55Sakib 2.85
1FROMpick the table
2WHEREkeep rows that are TRUE
3SELECTchoose columns, create aliases
4DISTINCTremove repeated rows
5ORDER BYsort (aliases already exist ✓)
6TOP / OFFSETcut down to the rows you asked for
That is why WHERE gpa > 3.5 fails but ORDER BY gpa works.
Putting it together

Six mistakes everyone makes (once)

1 · Double quotes for text

WHERE city = "Sylhet" WHERE city = 'Sylhet'

2 · = NULL

WHERE email = NULL WHERE email IS NULL

3 · Comma before FROM

SELECT name, cgpa, FROM … SELECT name, cgpa FROM …

4 · AND + OR without brackets

a OR b AND c (a OR b) AND c

5 · Alias in WHERE

WHERE [Credits Left] > 50 WHERE 144 - credits > 50

6 · TOP without ORDER BY

SELECT TOP 3 name … … ORDER BY cgpa DESC
In SQL Server, "double quotes" mean a column name, so "Sylhet" gives Invalid column name 'Sylhet'.

Recap

What to remember from today

📋

SELECT chooses columns, FROM the table. Use AS to rename and math to calculate.

🧹

DISTINCT removes repeated rows. ORDER BY sorts: ASC by default, DESC for big → small.

🥇

TOP n (with ORDER BY!) for “top 3”. OFFSET … FETCH for pages.

🔍

WHERE keeps TRUE rows. = <> > < >= <=. Text in 'single quotes'.

🔀

AND narrows, OR widens, brackets decide. IN = a list, BETWEEN = a range (ends included).

❔

LIKE with % and _. NULL = unknown: test with IS NULL, replace with COALESCE.
